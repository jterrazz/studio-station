# Station's window

The desktop window of station: a Tauri 2 shell around a React page set, and a client of the engine's socket. It shows what a Mac's engine answers through `station.api/v2` and decides nothing itself.

| Folder          | Holds                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/engine/`   | The client (`call`, `watch`), the read store behind its hooks and what keeps it fresh, its transports (Tauri, replay), the calls the bridge forwards (`bridged.ts`), the engine's errors, the gesture hook, the opener of an answer's address or command (`opener.ts`), the reader of the engine's words (`engine-words.ts`), and the law's four files: the words, the tones, the provisional reads and the word and tone a state is shown by (`shown.ts`) |
| `src/design/`   | The design components and tokens, each component's drawn states in a `<component>.stories.ts(x)` beside it, shown together by the gallery (`?page=gallery`, absent from the production build)                                                                                                                                                                                                                                                              |
| `src/tone.ts`   | The tones a state is drawn in: the one vocabulary `design/` and `engine/` share                                                                                                                                                                                                                                                                                                                                                                            |
| `src/shell/`    | The window's frame: sidebar, toolbar, routes; the pages are handed to it by `src/pages/registry.tsx`                                                                                                                                                                                                                                                                                                                                                       |
| `src/pages/`    | One folder per page or machine tab, its model beside it, its specs in `__tests__/`; `kit/` holds what every page renders                                                                                                                                                                                                                                                                                                                                   |
| `src/model/`    | Plain functions several pages read the same way: machines, formats, search                                                                                                                                                                                                                                                                                                                                                                                 |
| `src/fixtures/` | The engine's recorded answers per world (`worlds/`) and the harness a page spec renders over                                                                                                                                                                                                                                                                                                                                                               |
| `scripts/`      | The bench of the Linux VM: setup, checks, the recorder, the captures ([its page](scripts/README.md))                                                                                                                                                                                                                                                                                                                                                       |
| `src-tauri/`    | The Rust shell; its CLI reads the crate and `tauri.conf.json` from this folder                                                                                                                                                                                                                                                                                                                                                                             |

## The dependency rule

Each row is a layer of `typescript.architecture` in this folder's `studio.config.ts`, so `typescript check` run from `apps/window` fails an import that crosses it as `architecture/<name>`. A spec under `__tests__/` stands outside the map.

| From          | Never imports                             | Layer                  |
| ------------- | ----------------------------------------- | ---------------------- |
| `src/design/` | anything of the app but `src/tone.ts`     | `design-knows-no-app`  |
| `src/model/`  | anything of the app                       | `model-is-pure`        |
| `src/engine/` | `src/design/`, `src/shell/`, `src/pages/` | `engine-draws-nothing` |
| `src/shell/`  | `src/pages/`: `main.tsx` hands it `PAGES` | `shell-knows-no-page`  |

A component reaches whether an engine answers by `useReach()` (`src/engine/react.tsx`), never by a prop.

The root's `typescript check`, the one `make check` runs, does not read a member's layers yet: on 2026-11-13 a probe import crossing `model-is-pure` and `shell-knows-no-page` was refused from `apps/window` and passed from the root. The rule holds in the gate once `@jterrazz/typescript` reads each member's `typescript.architecture` from the member's folder, and an import from `src/engine/` into `src/design/` failing the root's check as `architecture/engine-draws-nothing` proves it.

## The law

- The engine owns every judgement: each verdict, state, count and sentence shown is a field it computed.
- The window owns layout and interaction: it never derives a state from numbers, never composes a verdict, never guesses a role.
- What no call gives is left empty in a way that does not lie, by `NoVerdict` or `NotGiven`, and named as a missing field.
- Whether an engine answers on the socket is the transport's state, `reachOf` (`src/engine/reach.ts`), read by every page and the sidebar through `useReach()`, and shown by a page's `Absent`, "No engine answers at <socket>", and by the sidebar's foot line in the same word, `ownState('engine-absent')`. The engine's own state (running, stopped) is `engine.read`'s alone, worded by `engineState` over `engineStateOf`.
- An enum the engine words (`@jterrazz/station-api/words.json`: a lifetime, a layer, a system, an OS, an architecture) is shown by its word through `src/engine/engine-words.ts` alone, the one module that reads the file, typed by `StationWords`. Any other enum code is shown by its word from `src/engine/words.ts` and its tone or colour from `src/engine/tones.ts`, each typed by the generated enum; a tone is the engine's `CoreVerdictTone` (`src/tone.ts`). What the wire does not carry yet (a state sent as booleans, a need's input, whether a port is shared, a row's gesture) is read once, in `src/engine/provisional.ts`, named for the field the engine owes.
- `src/engine/shown.ts` holds no table: it pairs a code's word with its tone into the `Shown` a state component draws, and shows a code no table has as it came, in the plain tone. The window's own states (a read not answered yet, a gesture done or of unknown outcome) are codes of `OwnState` in the same two tables, drawn through `ownState`.
- Those four files and the engine's reader are the only place a code becomes a word, a tone or a gesture, a confirmation's form included: `useGesture` reads it from `confirmFormOf`, and a page has no way to name one. Each table goes when its enum joins `words.json`.
- `src/engine/__tests__/words.test.ts` fails a page or a shell file that writes a tone or a word into `StatePill`, `StateDot` or `Verdict`, a tone literal into a state, a wire field (`PascalCase`) compared with a code, or a `Record` keyed by a wire type's field. It names its exceptions, each with its reason. It also fails, anywhere in `src/` but `engine-words.ts`, a `Words`, `Tones` or `Record` keyed by an enum `words.json` covers, by its name or by a field of `index.d.ts` that carries its codes, both read from the generated files, so the rule grows as the engine words more. It cannot see a lowercase wire field compared (`ports.list`, `accounts.list` and `activity.read` name theirs so), a code copied into a variable first, a `switch` over a code, or a word composed from a boolean: those stay the review's. The sweep of `src/pages/` and `src/shell/` for those four on 2026-11-13 found one, a disk's `Pending` worded inline, now `DISK_PENDING_WORD`.
- A code the generated type leaves a plain `string` or `number` has its words under one type, `WordsOfAnOpenCode`, and is shown as it came when the table has no word: a thermal level (`ActivitySample.thermal`), a port's reach (`PortsPort.Reach`), an account's reason and origin (`AccountsAccount`), a difference's two sides (`MachinefileDiffering`). A VM's `State` and the engine's are plain strings too; they are closed by the lists of `provisional.ts`.
- The one screen the window applies of its own is SAFETY, not judgement: a text shaped like a secret is drawn "Withheld" by `shownOrWithheld` (`src/design/secret.ts`), applied where a value and an engine's error text are drawn (`Value`, `ProgressLine`, `ConfirmDialog`, the kit's `Unanswered` and `Unknown`), `OpenButton` holds a value so shaped unopened, and an account's fields are named, never shown, by `screen`. Its spec proves a path, a version and an image digest are still shown.
- A mark is IDENTITY, not judgement, so the window draws it, the menu bar app's first: `markOf` (`src/design/app-marks.ts`) draws the menu bar's own mark for a name when it has one (15, `MENUBAR_MARKS`, reached through `ALIASES` for `gh`, `claude-desktop`, `github-release` and `kubectl`), else its [Simple Icons](https://simpleicons.org) logo (37 names, `LOGOS`), else its first two letters or digits. No call carries an icon (`CatalogApp.Bundle` names a macOS bundle the webview cannot draw), so `AppIcon` (`src/design/app-icon.tsx`) takes the engine's own name (`App.Name`, `Step.Item`, an account's `provider`, `DiskRow.App`); a setting is drawn by its first two letters (`LETTERED_KINDS`), as the mockup's tile is, even when it bears an app's name, and a name shaped like a secret by an empty tile. Every mark is drawn alike: one colour, the text tone, on the menu bar's 20 px box (a logo set on 16 px of it), in the mockup's raised 24 px tile, so no one can tell a source from another. The menu bar's marks have one owner, its `scripts/symbols.swift`: `scripts/menubar-marks.sh` writes `src/design/menubar-marks.ts` from it, and `menubar-marks.test.ts` fails when the two drift. The menu bar draws an account it has no mark for by the SF Symbol `key`, which a webview cannot draw: the window draws its two letters. The logos come from the package `simple-icons` pinned at 16.36.0 (CC0-1.0), their paths bundled and nothing fetched. The tables map a name to a drawing, never a code to a word or a tone, so the law spec leaves `src/design/` unswept and lists no exception for it.

## Adding a page

1. Its route: a name in `PLAIN_PAGES` or a tab in `TABS` (`src/shell/route.ts`), its case in `Body` (`src/pages/registry.tsx`).
2. Its folder under `src/pages/`: the page reads the engine with `useRead` or `useWatch`, and renders `Reading`, `Unanswered` and `NoVerdict` from `src/pages/kit/readings.tsx` for the states it does not have yet. A read is aimed by `targetOf` (`src/model/machines.ts`), so a read of this Mac names no target, the socket's engine being its own. It is one request per call, input and target compared by value (`src/engine/store.ts`): components asking the same share it, its input needs no `useMemo`, and every read is asked again when the engine restarts and kept fresh by the store ([below](#a-read-stays-fresh)); a page keeps no timer of its own for it.
3. Its calls in `scripts/record.py` (`asks`), recorded again over the worlds its specs use.
4. Its spec in `__tests__/`: its worlds loaded once before any render, `const recordingFor = await recordingsOf('two-macs', …)` (`src/fixtures/recordings.ts`), then `pageOver(recordingFor(world), route)` rendered by `component.render`, its tree compared to a golden in `__expected__/`.

## A read stays fresh

A watch the engine ends (`done`) and a plain read are an answer of one moment, so the read store (`src/engine/store.ts`, its triggers in `src/engine/fresh.ts`) asks again every read a component holds, and nothing else does.

- It asks on one cadence, `FRESH_EVERY` (30 s, the pace the engine reads its own pages at), at once when the window is shown again or regains a focus it lost (`src/engine/presence.ts`), and on each `notice` of `engine.events` where the engine's hello lists that call. A notice names no read, so it asks them all.
- It never asks while the window is hidden, never asks a read nobody holds, and never asks a read whose request is still out: a watch still streaming is live already.
- A re-ask never draws a loading or pending state over an answer shown: its outs are held until the watch ends, or shown at the next tick when it has not, and an error with no engine word keeps the answer.
- A gesture's `rereads` and an engine that restarts still ask at once, and show every out as it comes.
- Activity's five-second timer (`useActivity`, `src/pages/activity/reading.tsx`, which the tiles of Home and of a machine's Overview read through too) is a graph's pace, not this mechanism: it is the page's to move onto `useReread`.
- The timer goes when every engine the window reaches offers `engine.events` with a notice for each change a read shows: today the list is the HUD's (a server down, a VM ready), so a VM stopped from the CLI tells nothing, and the world's `guest serve` does not answer the call.

## The calls the bridge forwards

`src/engine/bridged.ts` lists the calls the window sends, and it is the one list. `src-tauri/build.rs` reads it into the Rust bridge, which refuses any other name before it reaches the engine: `refused`, code `bridge.not-bridged`, drawn like any refusal. `ReadName` and `WatchName` admit only its names, so a page that reads or makes a call off the list fails the compile, and `bridged.test.ts` fails a name of the list no source sends. A call joins the list in the commit that first sends it.

## What the window opens outside itself

Three buttons hand something to the Mac rather than to the engine: a VM header's Open in Terminal, a shared port's Open and an account's Sign in. They go through two Tauri commands of the shell, `open_url` and `open_in_terminal` (`src-tauri/src/opener.rs`), and nothing else in the window starts a program.

- The value is the engine's own: an `Openable` (`src/engine/opener.ts`) is made only from an answer, `machines.ssh`'s `Command`, an account's `hint`, a shared port's address, and its constructor is private, so no text a page holds reaches either command. The window appends nothing to it.
- A share's address opens from the window's Mac only when the engine's answer means it to: `ports.list` gives a share a `public` and a `local` address and nothing else, so its Open opens the public one, and the local one only on the row the engine flags `this_mac` (`shareOpensFromHere`, `src/engine/provisional.ts`). A share of another Mac with a local address alone keeps its Open held, its reason as its title (`LOCAL_ELSEWHERE`): `127.0.0.1` there is not this Mac's.
- `OpenButton` (`src/pages/kit/opens.tsx`) draws it: held with its reason as its title when no answer gives the value, the value as its title when one does, held too when the value is shaped like a secret (`looksSecret`, the guard Copy applies). Opening marks nothing done: the reads show what changed once the engine says so. Those three states are its stories in the gallery ([the design rules](#the-design-rules)).
- The Rust side checks again before the Mac sees anything. `open_url` takes one `http` or `https` URL with a host, at most 2048 bytes, with no space or control character, and opens it with `open` (`xdg-open` on Linux), the URL one argument and no shell between. `open_in_terminal` takes one line, at most 1024 bytes, with no control character (a line break, a NUL), writes it under a fixed header into a `.command` script of its own (mode 0700, in a 0700 folder of the temp folder), and opens that script with `open -a Terminal`. The script removes itself first, then runs the line; a script a terminal never ran is removed when the window starts. A refusal is `opener.not-a-web-address`, `opener.not-one-line` or `opener.not-opened`, drawn like the engine's.
- A `.command` file and not `osascript`, which the menu bar uses (`apps/menubar/sources/station-kit/engine/Terminal.swift`): Terminal runs it with no Automation consent, and the line is never quoted into AppleScript.
- The two commands need no capability: an app's own commands are allowed to a local page while the app declares no app manifest, as `engine_open` is, and refused to any remote origin (`tauri` 2.12.5, `src/webview/mod.rs`). `capabilities/default.json` and the CSP are unchanged, and no `shell` or `opener` plugin is linked.
- A debug build alone reads `STATION_WINDOW_OPENED`: set to a file, each command appends what it would open there (`url<TAB><url>`, `terminal<TAB><script><TAB><command>`) and opens nothing, so a bench session proves the plumbing with no browser or terminal; a release build compiles that path out.

## Making a gesture

A gesture is a call that changes something, and every one goes through `useGesture(call, spec)` (`src/engine/use-gesture.ts`), rendered by `GestureButton` and `GestureOutcome` (`src/pages/kit/gestures.tsx`).

- It asks before it sends when `calls.json` declares the call's confirmation (`CONFIRMED`, `src/engine/confirms.ts`): a yes, or the name typed when `confirmFormOf` (`src/engine/provisional.ts`) says so for the call. The hook reads the form itself, so a page names none.
- It runs while the engine sends progress, and settles done on the out or failed on the error, shown by `Unanswered` with its hint and fix.
- It settles unknown, never failed, when its connection drops after it was sent or it hears nothing for its `within` (10 minutes by default): the engine may have done it, so the reads are asked again and show what it now says.
- An engine refusal of type `needs-confirmation` asks again in the level the engine names; the window never judges whether a gesture is allowed.
- Once settled, every read the spec names in `rereads` is read again, and every watch of it opens again.
- A gesture of a row renders through `GestureRow`: its progress and its refusal take a line of their own under the row, never its trail, and its Done sits in the trail at the left of its button, so the row keeps its height; a machine's header draws Start and Stop's Done the same way.
- Its state is held by its request's value (`src/engine/gesture-store.ts`), not by the component: a row the engine's next answer leaves out for a moment (a watch read again answers pending first) finds its outcome when it comes back. Two buttons of one request share it, and the dialog is the one clicked's.
- Its dialog belongs to the request too: the button clicked hands its title and verb to the store, and `GestureConfirm` (`src/pages/kit/gestures.tsx`) draws the one dialog asking, handed to the shell as `Pages.Confirm` and drawn after its sheets, so a row rebuilt while it asks leaves the dialog open. A spec rendering a gesture outside `Window` and `pageOver` renders `GestureConfirm` beside it.
- Its outcome, once done, is drawn where the row stands, by `GestureRow`, while the re-read still lists that row. A row the re-read removes takes its outcome to `HeldOutcomes`, the panel "Done here" above the list, so it outlives the row (a need fixed from the Needs panel too, so each page that draws the panel holds it in one); a gesture of the whole list (Free what can be rebuilt, one `disk.free {}` per page) holds each of its outcomes there too, by `HoldsWhenDone`.
- Its confirmation is `ConfirmDialog`: a gesture drawn `danger`, or one confirmed by its name typed, confirms on the filled `destroy` button, and the line under its title is the `message` of the engine's refusal when it sends one, else nothing: no call gives a consequence yet (the table above).

A gesture is recorded by naming it in `GESTURES` of `scripts/record.py`, with its world and its input, `Confirm` included; `record.py <world>` then sends it to a fresh world build and writes `worlds/<world>/gestures/<call>.json` with every read whose answer it changed. Its spec renders the page over that world, clicks through the dialog, and sees the reads change; the replay plays each recorded frame `?pace=<ms>` apart in a dev or proof build, so a capture can catch the running state.

## The design rules

- No inline style. A size computed from data is the one accepted form: a CSS custom property set on the element, typed `Measured` (`src/design/measure.ts`), which the module's CSS draws (`width: var(--fill)`). A colour, a spacing or a tone is a class, never a value written inline.
- A control that acts is drawn pressed on one token, `raise-2`: a button, an icon button, a switch's option, a nav item, a choice card and a row that opens. A button also sinks by `--motion-press`, the hierarchy's press scale, and a filled one (primary, destroy) keeps its fill, as `raise-2` would erase it.
- A button takes one of five looks, named once in `BUTTON_VARIANTS` (`src/design/button.tsx`): `primary` leads a screen, `plain` is any other gesture, `link` reads as a sentence, `danger` opens a destruction, and `destroy`, the filled danger, only confirms one. `destroy` is drawn by `ConfirmDialog` alone, and the button spec fails a page that names it.
- A component's states are its stories: a plain array of `{ name, props }` (`Story`, `src/design/story.ts`) in `<component>.stories.ts(x)` beside it, covering each variant and the data states it can meet (empty, long text, missing, withheld, disabled). The gallery renders one entry per component, grouped by layer, from `src/pages/gallery/entries.ts`, and its spec fails a component `src/design/index.ts` exports without an entry. A kit component a page draws in states of its own has its stories beside it too: `OpenButton`'s, drawn on an engine of its own whose opener is `NO_OPENER` (`OpenButtonSample`), so the gallery opens nothing.
- A read asked again draws nothing: no refreshing mark, no `Reading` over an answer already shown, proved by the engine's react spec. A link still connecting is the sidebar foot's `Engine connecting`, its word `OWN_STATE_WORDS.connecting`, never a read under way.

## The window's chrome on a Mac

On a Mac the window is drawn as a native app with a unified toolbar: its traffic lights sit in the top bar's row, over a discreet vibrancy. Everywhere else (the Linux bench's WebKitGTK, a headless capture, a page outside Tauri) it is drawn opaque, as before.

- The top bar's row is one token, `--chrome-row` (46 px, `src/design/tokens.css`): the toolbar's height, and on a Mac the sidebar's first row, which holds the lights and is a drag region. The lights are placed by `trafficLightPosition` (`src-tauri/tauri.conf.json`) at `x: 18`, the inset Finder's own lights have on macOS 26, and `y: 25.5`, which centres them on that row: `tao` grows the title bar to the button's height plus `y`, and the button's centre lands 2.5 pt above `y` (measured on macOS 26.6, `y: 16` drew it at 13.5 pt). A row height that changes moves `y` by the same half.
- With the sidebar hidden the toolbar keeps `--chrome-lights-room` (84 px) at its left for the lights. In fullscreen the lights are gone, so `wearDress` (`src/shell/chrome.ts`) drops `data-chrome` while the window fills the screen, and the sidebar and toolbar draw their plain spacing, as off a Mac.
- The material is one `underWindowBackground` effect under the whole window, its state following the window's (`windowEffects`), on a window made `transparent` and dark (`theme`, so the effect is the dark material whatever the system's appearance). Over it the canvas is drawn at `--material-canvas` (86 %) and the sidebar at `--material-sidebar` (72 %), through `--ground` and `--ground-sidebar`; panels, wells and every colour token stay opaque, so text keeps its contrast.
- `data-material="vibrant"` is set by `wearDress` in the Tauri window on a Mac alone (the user agent says `Macintosh`), so the translucent tokens apply nowhere else, and no golden moves.
- Transparency uses macOS's private API, which `tauri` enables unconditionally since 2.12.1 (`macOSPrivateApi` is a no-op there), hence `tauri = "2.12.1"` in `Cargo.toml`: the window is not for the App Store. No capability and no CSP changed.
