# The status contract

`station status --json` prints one JSON document, `station.status/v1`, and `studio doctor` reads it to judge the machine.

## The document

The top-level keys, in order:

| Key            | Holds                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `schema`       | `station.status/v1`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `generated_at` | The moment of the reading, RFC 3339 in UTC                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `station`      | `version` and `commit` of the binary that answered; on a host `engine` (`state`, `running`, `version`: station's engine, `absent` before tart is installed)                                                                                                                                                                                                                                                                                                                                                                                  |
| `machine`      | `name` (`null` when unregistered), `kind` (`host`, `linux`, `macos`), `hostname`, `os`, `arch`, `user`, `shell`                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `system`       | `uptime`, `battery`, `cpu` and `memory.top` (the busiest processes: `pid`, `name`, `value`), `memory.total_bytes`                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `environment`  | `network`, `security` and `updates` (checks), `ports` (`pid`, `name`, `port`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `workspace`    | `disk` (`name`, `level`, `bytes`: one per storage row placed here and level, then `other`, the caches no such row claims), `strays` (`name`, `path`, `bytes`, `repair`); `repositories`, `dependencies` and `docker` stay for v1 readers and are always empty                                                                                                                                                                                                                                                                                |
| `tools`        | One object per catalogue app placed here: `name`, `category`, `method`, `places`, `state`, `version`, `managed`, `provides`, `detail`, `use` (`station apps --json` is `station.apps.list/v1`, [Commands](commands.md#station-apps))                                                                                                                                                                                                                                                                                                         |
| `config`       | One object per config item placed here, as the overview reads it                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `setup`        | `state` and `steps` (`name`, `state`, `detail`) of `station setup`                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `identity`     | Checks: git email, name and signing, gpg key, github, ssh key                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `background`   | Jobs: every non-Apple launchd job of `~/Library/LaunchAgents`, `/Library/LaunchAgents`, `/Library/LaunchDaemons` and every running one of the user domain without a plist; each `label`, `group` (`station`, `known`, `unknown`, `orphan`), `state` (`running`, `idle`, `failing`, `not-loaded`, `unknown`), `mark` (`ok`, `attention`, `absent`, `broken`), `pid`, `last_exit`, `scope` (`user`, `root`), `owner`, `plist`, `program` and, for a failing or orphan job, the `removal` command station shows and never runs (`""` otherwise) |
| `gateways`     | Checks: `Tailscale Serve` on a host whose tailnet is connected                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `tailnet`      | `state`, `connected`, `backend_state`, `name`, `ip`, `dns_name`: the Tailscale app's node, read only; `variant` (`standalone`, `app-store` or `""`) and `cli`, the absolute path of the CLI station ran (`""` when absent)                                                                                                                                                                                                                                                                                                                   |
| `power`        | a host with Power whose engine answers: `held`, and while held `lid` and `until` (RFC 3339) ([Commands](commands.md#station-power)); absent elsewhere                                                                                                                                                                                                                                                                                                                                                                                        |

A check is `{"name": "filevault", "state": "ok", "value": "on", "detail": ""}`. `workspace.docker` is `{state, containers, images, volumes, dangling_bytes, total_bytes}`, its state always `unknown`: station no longer scans the workspace. `environment.network` is the `local ip` and the `dns` resolvers, both read on the machine: a status read calls no third-party service.

The `macos` update reads the list the background check wrote to `/Library/Preferences/com.apple.SoftwareUpdate.plist` (`<n> pending` or `up to date`, detail `checked <age> ago`); `softwareupdate -l` runs only when that list is missing or older than 7 days. `environment.security` and `environment.updates`, `background` and `gateways` are macOS-only: they are `[]` on a Linux machine. The `setup.steps` of a host are `name`, `zshrc`, `layout` and `tools` (`degraded` while the App Store app's [CLI wrapper](machines.md#the-tailnet) is due); a machine that is not a host leaves out `name`, `layout` and `tools`.

`remote-login` and `encrypted-dns` are read from the state of the `sshd` and `dns` config items, so `status` and `station settings` cannot disagree about them. A machine where those items are not placed has no such row.

`Tailscale Serve` is `ok` with value `on` when the tailnet lists a certificate domain, else `degraded`, value `off`, detail `Serve is off on the tailnet: enable HTTPS certificates in the Tailscale admin console`; the tailnet logged out or absent, or a VM, has no such row.

## Rules of the encoding

Every `state` is one of `ok`, `degraded`, `absent`, `broken` or `unknown`.

Arrays are never `null`: an empty one is `[]`. The only `null` is `machine.name` on a machine that is not registered.

Numbers are JSON numbers, sizes are `*_bytes` and `generated_at` is RFC 3339 in UTC.

Every probe runs under its own deadline, counted from its start: 2 s by default, 5 s for `gh auth status`, 10 s for `brew outdated` and `softwareupdate -l`. A probe past its budget answers `unknown`, value `?`, detail `no answer in <budget>`, so the command is bounded by about 10 s on a Mac and finishes well under 6 s where every tool is missing.

No kept secret reaches the document.

## Stability

A field is only ever added within v1. A rename or a removal makes the document `station.status/v2`.

The Go structs behind the document are `src/present/status/json.go`, their only definition, and `src/present/status/json_test.go` pins the encoding of a fixed snapshot byte for byte.

## Who reads it

`studio doctor` runs `station status --json` and reads `station`, `tools[].{name,provides,state,version}` and `tailnet.{state,connected,backend_state}`. Its decoder lives in the OS repository, in the station connector of its connectors package.
