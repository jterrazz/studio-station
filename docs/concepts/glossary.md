# Glossary

One word per concept, one concept per word: the words below are the only ones the code, the help, the docs and the output use for these concepts.

| Section       | Answers                                             |
| ------------- | --------------------------------------------------- |

Code identifiers follow the words (`Host`, `VM`, `Lifetime`, `Place`). A word listed as rejected never appears for that concept; every other page links here and defines nothing. The one spelling rule: "catalogue" in prose, `catalog` in Go (the package name; same word).

## The words

| Word                       | Means (one line)                                                                                                                                                                                                                                                                                                                                                | Rejected, and why                                                                                                                                                                     |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **station**                | the CLI and its repository (`studio-station`)                                                                                                                                                                                                                                                                                                                   | workstation (D0)                                                                                                                                                                      |
| **machine**                | any computer of the fleet: a host or a VM                                                                                                                                                                                                                                                                                                                       | node (Tailscale's word for a HOST's identity, below), box (slang), device (Apple's word for the iPhone)                                                                               |
| **host**                   | a physical Mac the owner owns; it runs station and may run VMs                                                                                                                                                                                                                                                                                                  | pilot/worker, client/server, role (every host is equal: F2 "symmetric"), metal, hypervisor (names the software, not the Mac)                                                          |
| **VM**                     | a virtual machine running on one host, cloned from an image; `VM` in Go, `vm` in flags and placeholders; never on the tailnet: reached through its host (round 5, N1)                                                                                                                                                                                           | guest (for the MACHINE: the word names station's in-VM agent since round 5, below), sandbox (taken by macOS and Claude Code), instance (cloud word), container (no own kernel: wrong) |
| **fleet**                  | the set of all machines: every host and the VMs on each                                                                                                                                                                                                                                                                                                         | estate (the OS's word for its repositories), cluster (implies a scheduler), park                                                                                                      |
| **kind**                   | what a machine is: `host`, `linux` (a Linux VM) or `macos` (a macOS VM)                                                                                                                                                                                                                                                                                         | type (Go keyword), os (a host runs macOS too), platform. | **image**                  | a versioned, read-only VM disk a VM is cloned from: `linux` now, `macos` later                                                                                                                                                                                                                                                                                  | template (Lima's word for a config file), golden image (jargon), base (below)                                                                                                         |
| **base**                   | the upstream image an image is built from (`ghcr.io/cirruslabs/ubuntu`)                                                                                                                                                                                                                                                                                         | parent, source                                                                                                                                                                        |

| **user**                   | the login on a machine: a host's is the owner's per host (`--user`), every VM's is the fleet's one `vm_user`                                                                                                                                                                                                                                                    | account (taken by the keychain), login (verb)                                                                                                                                         |
| **ip**                     | a numeric address: a host node's 100.x (`ip`) or a VM's NAT address (`Engine.IP`, resolved at each use by `machines pipe` and the engine, never written into a block); always the key `ip` in JSON                                                                                                                                                              | address (vague: names, IPs and `user@name` all were "addresses" in round 2's first draft), target                                                                                     |
| **tailnet**                | the owner's Tailscale network                                                                                                                                                                                                                                                                                                                                   | VPN, mesh                                                                                                                                                                             |
| **node**                   | a HOST's identity on the tailnet, held by the Tailscale app: its name, 100.x ip, MagicDNS name; a VM has none (round 5, N1)                                                                                                                                                                                                                                     | device (Tailscale's console word; taken here), peer (only "another node")                                                                                                             |
| **place**                  | the kinds of machine a catalogue entry may live on (`host`, `linux`, `macos`): Dia's place is `host`, browser-use's `linux macos`, node's all three                                                                                                                                                                                                             | scope, target, location, "lives on"                                                                                                                                                   |
| **catalogue**              | station's built-in list of what it can put on a machine: tools (agent skills included, each with its storage row), config items, shortcuts, images                                                                                                                                                                                                              | registry (now only an OCI image registry), manifest (the OS's word)                                                                                                                   |

| **config**                 | the family of config items (`station config`); and, as a storage level, a tool's own configuration files, what a config item usually writes (round 4: the owner's level name, S4; one concept seen from two sides: what sets a tool up)                                                                                                                         | (station's own file is **settings**)                                                                                                                                                  |
| **settings**               | station's own file, `~/.config/station/preferences.json`: here, the hosts, `vm_user`, the lend list, the git identity, the services policy (round 5; the round-2 `tailnet` key is dropped)                                                                                                                                                                      | config (taken by the item family), preferences                                                                                                                                        |
| **skill**                  | an agent skill (a `SKILL.md` folder) from a community repository: a catalogue TOOL whose method is `skill` (installed with the `skills` CLI), category "Agent skills"; there is no `skills` family (round 3, A1: a skill is installed content, not config)                                                                                                      | plugin, prompt                                                                                                                                                                        |

| **lease**                  | the sticky reservation of one host port for one (VM, guest port), kept in the host's lease store `~/.local/state/station/leases.json` until released (delete, a temporary VM's poweroff, `services release`, 7 idle days; a profile's lease is **pinned** and never idles out)                                                                                  | binding, allocation, mapping, reservation (the act is "reserve")                                                                                                                      |
| **publish**                | to make a leased service reachable: ONE host listener on 127.0.0.1 (never the tailnet ip, 0.0.0.0 or ::), each connection carried into the VM by `direct-tcpip`, exposed on the tailnet by tailscaled while **Serve** is on (`tailscale serve --https` for HTTP, `--tcp` for any other TCP); **unpublish** is its reverse, the lease kept                       | expose (Docker's, vague about where), share, forward, open                                                                                                                            |
| **profile**                | a catalogue entry naming a dev tool's guest port and the environment variables that carry its public URL (`expo` 8081 `EXPO_PACKAGER_PROXY_URL`, `vite` 5173); its port is reserved at create and its variables, rendered at every run of the VM, exported by the VM's shell (round 5, N9)                                                                      | preset, template (Lima's word), recipe (taken), integration                                                                                                                           |
| **public host**            | the host's MagicDNS name (`macbook.tail1234.ts.net`) while Serve is on, `127.0.0.1` while it is off: the host part of every public URL; `STATION_PUBLIC_HOST` in a VM                                                                                                                                                                                           | domain, hostname (macOS's own setting)                                                                                                                                                |

## The verbs

A destroying verb has no synonym in the tree. One verb per meaning:

`install/uninstall/upgrade` (catalogue entries), `setup` (here: registered,
its shell wired, its files in place), `add/forget` (other hosts: registered
and forgotten, never touched), `create/delete` (VMs: made and
DESTROYED; `delete` is the only destroying machine verb), `start/stop/restart`
(running state; never destroys), `allow/disallow` (the lend list),
`lend/recall` (copies of lent secrets), `build`
(images), `clean/reset` (a tool's storage: `clean` empties caches and asks
nothing; `reset` deletes data, always named and confirmed), `release` (a
lease; `services url` reserves one and prints its URL). Round 5 deletes
`up/down` (the tailnet is the Tailscale app's: station only reads it).

## Default names

A VM's default name is `<image>-<n>` (`linux-1`, `linux-2`, `macos-1`), `n` being the smallest integer from 1 that no VM record on any host of the fleet uses and no host's name uses. A VM is not on the tailnet, so no node holds a VM's name.

`--name` overrides it: lowercase letters, digits and `-`, 1 to 40 characters, refused if taken. A host's name is the owner's, asked at `station setup`; the recommendation is the plain model name: `macbook`, `mac-mini`.
