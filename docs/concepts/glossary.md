# Glossary

One word per concept, one concept per word: the words below are the only ones the code, the help, the docs and the output use for these concepts.

Code identifiers follow the words (`Host`, `VM`, `Lifetime`, `Place`). A word listed as rejected never appears for that concept; every other page links here and defines nothing. The one spelling rule: "catalogue" in prose, `catalog` in Go (the package name; same word).

## The words

| Word                       | Means (one line)                                                                                                                                                                                                                                                                                                      | Rejected, and why                                                                                                                                                                           |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **station**                | the CLI and its repository (`studio-station`)                                                                                                                                                                                                                                                                         | the product's earlier name                                                                                                                                                                  |
| **machine**                | any computer of the fleet: a host or a VM                                                                                                                                                                                                                                                                             | node (Tailscale's word for the identity, below), box (slang), device (Apple's word for the iPhone)                                                                                          |
| **host**                   | a physical Mac the owner owns; it runs station and may run VMs                                                                                                                                                                                                                                                        | pilot/worker, client/server, role (every host is equal), metal, hypervisor (names the software, not the Mac)                                                                                |
| **VM**                     | a virtual machine running on one host, cloned from an image; `VM` in Go, `vm` in flags and placeholders                                                                                                                                                                                                               | guest (hypervisor jargon, and in Tart/Lima "guest" names the OS inside, not the machine), sandbox (taken by macOS and Claude Code), instance (cloud word), container (no own kernel: wrong) |
| **fleet**                  | the set of all machines: every host and the VMs on each                                                                                                                                                                                                                                                               | estate (the OS's word for its repositories), cluster (implies a scheduler), park                                                                                                            |
| **kind**                   | what a machine is: `host`, `linux` (a Linux VM) or `macos` (a macOS VM)                                                                                                                                                                                                                                               | type (Go keyword), os (a host runs macOS too), platform; the install `Kind` (brew, cask...) is called **method**                                                                            |
| **image**                  | a versioned, read-only VM disk a VM is cloned from: `linux` now, `macos` later                                                                                                                                                                                                                                        | template (Lima's word for a config file), golden image (jargon), base (below)                                                                                                               |
| **base**                   | the upstream image an image is built from (`ghcr.io/cirruslabs/ubuntu`)                                                                                                                                                                                                                                               | parent, source                                                                                                                                                                              |
| **recipe**                 | the script, embedded in station, that turns a base into an image                                                                                                                                                                                                                                                      | spec (taken by `specs/`), Dockerfile (wrong tool), provisioner                                                                                                                              |
| **lifetime**               | whether a VM is meant to last: `temporary` or `lasting`; the flag `--lifetime`, asked at every create                                                                                                                                                                                                                 | durability, persistence                                                                                                                                                                     |
| **temporary**              | a VM that ends with its run: a guest `poweroff` deletes it, a host reboot leaves it stale (`machines delete` reclaims it), `delete` deletes it on purpose; a guest `reboot` and any stop station cannot read as a poweroff NEVER delete it                                                                            | ephemeral (Tailscale's word for a node property station no longer uses), disposable (every VM is disposable), throwaway, temp                                                               |
| **lasting**                | a VM that stays until deleted; stopped, it stays stopped; running, it comes back up with its host                                                                                                                                                                                                                     | persistent (jargon), durable, pet, kept (taken by the secret tier)                                                                                                                          |
| **here**                   | the machine station is running on; also the settings key `here`                                                                                                                                                                                                                                                       | self, local, this machine (fine in prose)                                                                                                                                                   |
| **name**                   | a machine's ONE name, used everywhere: settings, tailnet node, `~/.ssh/config` Host, Herdr, `--on`                                                                                                                                                                                                                    | alias, hostname (macOS's own setting, may differ; never an input), address (a name is not an address)                                                                                       |
| **user**                   | the login on a machine: a host's is the owner's per host (`--user`), every VM's is the fleet's one `vm_user`                                                                                                                                                                                                          | account (taken by the keychain), login (verb)                                                                                                                                               |
| **ip**                     | a numeric address: a node's 100.x (`ip`) or a VM's NAT address (`Engine.IP`); always the key `ip` in JSON                                                                                                                                                                                                             | address (vague: names, IPs and `user@name` all were "addresses"), target                                                                                                                    |
| **tailnet**                | the owner's Tailscale network                                                                                                                                                                                                                                                                                         | VPN, mesh                                                                                                                                                                                   |
| **node**                   | a machine's identity on the tailnet: its name, 100.x ip and tags                                                                                                                                                                                                                                                      | device (Tailscale's console word; taken here), peer (only "another node")                                                                                                                   |
| **place**                  | the kinds of machine a catalogue entry may live on (`host`, `linux`, `macos`): Dia's place is `host`, browser-use's `linux macos`, node's all three                                                                                                                                                                   | scope, target, location, "lives on"                                                                                                                                                         |
| **catalogue**              | station's built-in list of what it can put on a machine: tools (agent skills included, each with its storage row), config items, shortcuts, images                                                                                                                                                                    | registry (now only an OCI image registry), manifest (the OS's word)                                                                                                                         |
| **tool**                   | a catalogue entry that is installed content: software or an agent skill; installed, uninstalled, upgraded                                                                                                                                                                                                             | app, package                                                                                                                                                                                |

| **config**                 | the family of config items (`station config`); and, as a storage level, a tool's own configuration files, what a config item usually writes: one concept seen from two sides, what sets a tool up                                                                                                                     | (station's own file is **settings**)                                                                                                                                                        |
| **settings**               | station's own file, `~/.config/station/settings.json`: here, the hosts, the tailnet auth choice, `vm_user`, the lend list, the git identity                                                                                                                                                                           | config (taken by the item family), preferences                                                                                                                                              |
| **skill**                  | an agent skill (a `SKILL.md` folder) from a community repository: a catalogue TOOL whose method is `skill` (installed with the `skills` CLI), category "Agent skills"; there is no `skills` family: a skill is installed content, not config                                                                          | plugin, prompt                                                                                                                                                                              |

| **data**                   | a storage level: state the owner may wipe to factory (histories, databases, simulator devices); only `storage reset <tool>` removes it, named and confirmed                                                                                                                                                           | state (XDG's folder name, not a level), user data                                                                                                                                           |
| **stray**                  | a declared home-root folder a tool writes when its relocation is missing or was never applied (`~/go`, `~/.npm`, `~/.tart`); `status` shows it `◐` with its repair                                                                                                                                                    | pollution, leftover, orphan                                                                                                                                                                 |
| **system**                 | a host tool the fleet depends on, installed by `setup` (`homebrew mise git tailscale tart`); `use: system` in JSON (the status JSON key `system`, the machine's resources, predates it and stays: contract v1)                                                                                                        | core, required, base                                                                                                                                                                        |
| **exploration**            | every other tool placed on a host: the owner's own, allowed there, never called by station or its agents; builds go through VMs                                                                                                                                                                                       | fun, personal, optional, dev tool                                                                                                                                                           |
| **shortcut**               | a canned command sequence under `station run` (git, docker)                                                                                                                                                                                                                                                           | alias (zsh word), macro, recipe (taken)                                                                                                                                                     |
| **secret tier**            | how far a secret may travel: kept, lent or bound                                                                                                                                                                                                                                                                      | admin/operator/identity (`operator` collides with the OS credential namespace `operator:*`)                                                                                                 |
| **kept**                   | what station never moves, copies or deletes: as a secret tier, a secret that never leaves the host's keychain (the VM-join client, the host's tailnet auth key, `AGENT_PASSWORD`); as a storage level, keys, credentials, the node identity and the VM records, never cleaned or reset: one concept, "it stays"       | admin, root, host secret, protected                                                                                                                                                         |
| **lent**                   | a secret on the lend list: it lives on the host; `lend` delivers a COPY (a snapshot) to a VM, `recall` takes the copy back, `delete` destroys it with the VM                                                                                                                                                          | operator, shared, delegated, copied                                                                                                                                                         |
| **bound**                  | a secret born inside one VM: its node key, its ssh host keys, its own `github-login` token                                                                                                                                                                                                                            | identity, ephemeral, own                                                                                                                                                                    |

## The verbs

A destroying verb has no synonym in the tree. One verb per meaning:

`install/uninstall/upgrade` (catalogue entries), `setup` (here: registered,
its shell wired, its files in place), `add/forget` (other hosts: registered
and forgotten, never touched), `create/delete` (VMs: made and
DESTROYED; `delete` is the only destroying machine verb), `start/stop/restart`
(running state; never destroys), `allow/disallow` (the lend list),
`lend/recall` (copies of lent secrets), `up/down` (the tailnet), `build`
(images), `clean/reset` (a tool's storage: `clean` empties caches and asks
nothing; `reset` deletes data, always named and confirmed).

## Default names

A VM's default name is `<image>-<n>` (`linux-1`, `linux-2`, `macos-1`), `n` being the smallest integer from 1 that no VM record on any host of the fleet uses, no online node uses, and no node that station did not tag (`tag:station-vm`) uses. An offline `tag:station-vm` node with no record anywhere is a leftover and does not hold its name.

`--name` overrides it: lowercase letters, digits and `-`, 1 to 40 characters, refused if taken. A host's name is the owner's, asked at `station setup`; the recommendation is the plain model name: `macbook`, `mac-mini`.
