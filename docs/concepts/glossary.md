# Glossary

One word per concept, one concept per word: the words below are the only ones the code, the help, the docs and the output use for these concepts.

| Section               | Answers                                            |
| --------------------- | -------------------------------------------------- |
| The words             | Every term, what it means, and the words it is not |
| The words of the code | The architecture's words, in Go and the docs only  |
| The verbs             | One verb per meaning, and which one destroys       |
| Default names         | How a VM and a Mac get their name                  |

Code identifiers follow the words (`Computer`, `VM`, `Lifetime`, `LivesOn`). A word listed as rejected never appears for that concept, and the words v3 retired are refused everywhere by `specs/architecture/banned_test.go`; every other page links here and defines nothing. The one spelling rule: `catalog`, in Go, in paths and in prose; a page that still says "catalogue" means the same word.

## The words

| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| **station**              | the CLI and its repository (`studio-station`)                                                                                                                                                                                                                                                                                                                                                        | workstation (D0)                                                                                                    |
| **machine**              | any computer station knows: a Mac or a VM                                                                                                                                                                                                                                                                                                                                                            | node (Tailscale's word for a Mac's identity, below), box (slang), device (Apple's word for the iPhone)              |
| **Mac**                  | a physical Mac the owner owns, the kind `computer` on the system macOS; it runs station and its engine, and may run VMs                                                                                                                                                                                                                                                                              | pilot/worker, client/server, role (every Mac is equal), metal, hypervisor (names the software)                      |
| **This Mac**             | the Mac in front of you, `this_mac: true` in JSON                                                                                                                                                                                                                                                                                                                                                    | local, current                                                                                                      |
| **All machines**         | every Mac and the VMs on each (`--all-machines`)                                                                                                                                                                                                                                                                                                                                                     | estate (the OS's word for its repositories), cluster (implies a scheduler), park                                    |
| **VM**                   | a virtual machine on one Mac, cloned from an image; `VM` in Go, `vm` in flags and placeholders; never on Tailscale: reached through its Mac                                                                                                                                                                                                                                                          | guest (station's in-VM agent, below), instance (cloud word), container (no own kernel: wrong)                       |
| **Workspace**            | a VM set up by station for you and your agents, ephemeral or persistent                                                                                                                                                                                                                                                                                                                              | instance, box                                                                                                       |
| **agent**                | a coding agent at work on a workspace, in a Herdr terminal of its own, named uniquely across every machine (`review-bot`, `linux-1·2`); its lifecycle is its own: stopping it never touches its workspace                                                                                                                                                                                            | session (the app's own id, never an agent's address)                                                                |
| **Server**               | a VM kept always on, managed inside by your own tooling                                                                                                                                                                                                                                                                                                                                              | always-on VM                                                                                                        |
| **kind**                 | what a machine is: `computer`, `workspace` or `server` (a Mac is a computer whose system is macOS); the system is its own word                                                                                                                                                                                                                                                                       | type (Go keyword), platform                                                                                         |
| **system**               | a machine's operating system: `{os, version, arch}`, `macOS` or `Linux`                                                                                                                                                                                                                                                                                                                              | os alone, platform                                                                                                  |
| **image**                | a versioned, read-only VM disk a VM is cloned from: `linux` now, `macos` later                                                                                                                                                                                                                                                                                                                       | template (Lima's word), golden image (jargon), base (below)                                                         |
| **base**                 | the upstream disk an image is built from                                                                                                                                                                                                                                                                                                                                                             | parent                                                                                                              |
| **recipe**               | the script, embedded in station, that turns a base into an image                                                                                                                                                                                                                                                                                                                                     | spec (taken by `specs/`), Dockerfile (wrong program), provisioner                                                   |
| **lifetime**             | whether a workspace is `ephemeral` (the default) or `persistent` (`--persistent`); a server's is always on                                                                                                                                                                                                                                                                                           | durability, throwaway and permanent (the v3 words: `--permanent` and the stored values still read, for one release) |
| **Ephemeral**            | a workspace a guest `poweroff` deletes (the engine does); a `stop` keeps it with its disk until `start` or `delete`; a crash keeps it, `ended unexpectedly`; it never restarts by itself                                                                                                                                                                                                             | throwaway, disposable, temp                                                                                         |
| **Persistent**           | a workspace that stays until deleted; a guest `poweroff` or a `stop` leaves it stopped until `start`; it never restarts by itself                                                                                                                                                                                                                                                                    | permanent, durable, pet, kept (taken by the secret tier)                                                            |
| **wanted state**         | the state you want a VM in: Running or Stopped                                                                                                                                                                                                                                                                                                                                                       | desired, target                                                                                                     |
| **health**               | the four steps that tell a VM is well: Running, Has an address, SSH answers, Check passes                                                                                                                                                                                                                                                                                                            | liveness, readiness (taken, below)                                                                                  |
| **health check**         | a server's optional URL or `host:port` (`--check`), the fourth step of its health; the only "check" in station                                                                                                                                                                                                                                                                                       | monitor                                                                                                             |
| **name**                 | a machine's ONE name, used everywhere: preferences, a Mac's Tailscale node, the `~/.ssh/config` block, Herdr, `--on`                                                                                                                                                                                                                                                                                 | alias, hostname (macOS's own setting, may differ; never an input), address                                          |
| **user**                 | the login on a machine: a Mac's is the owner's per Mac (`--user`), every VM's is the one `vm_user`                                                                                                                                                                                                                                                                                                   | account (taken, below), login (verb)                                                                                |
| **ip**                   | a numeric address: a Mac node's 100.x (`ip`) or a VM's address behind its Mac (`Engine.IP`, resolved at each use); always the key `ip` in JSON                                                                                                                                                                                                                                                       | address (vague), target                                                                                             |
| **behind its Mac**       | how a VM reaches the network by default (`--network nat`); **bridged** (`--network bridged`) gives it its own address on your LAN                                                                                                                                                                                                                                                                    | (jargon)                                                                                                            |
| **node**                 | a Mac's identity on Tailscale, held by the Tailscale app: its name, 100.x ip, MagicDNS name; a VM has none                                                                                                                                                                                                                                                                                           | device (Tailscale's console word; taken), peer (only "another node")                                                |
| **lives on**             | the kinds of machine a catalog item may live on: Mac only, every machine, VMs only                                                                                                                                                                                                                                                                                                                   | scope, target, location                                                                                             |
| **catalog**              | what station can put on a machine, one item file each (`station.catalog/v1`, `src/catalog/items/<category>/<name>.yaml`): managers, apps (agent skills included, each with its disk row) and settings; it defines, a Machinefile chooses. Images and profiles are still values beside it                                                                                                             | registry (an OCI image registry only), manifest (the OS's word)                                                     |
| **item**                 | one file of the catalog: a manager, an app or a setting, its methods and, for an app, its disk row                                                                                                                                                                                                                                                                                                   | entry (a v3 Go value of the catalog)                                                                                |
| **app**                  | a catalog item that is installed content: software or an agent skill; installed, updated, removed (`station apps`)                                                                                                                                                                                                                                                                                   | package                                                                                                             |
| **method**               | how an item installs or applies: one manager key and the selector of the machines it fits; brew, cask, mas, mise, npm, bun, uv, script, skill, provided-by (it comes with another item), manual; a setting's file, builtin                                                                                                                                                                           | manager (the item a method runs, below)                                                                             |
| **manager**              | a catalog item of kind `manager`: one that installs other items (homebrew, mise, mas, uv, bun, node for npm, the skills CLI)                                                                                                                                                                                                                                                                         | method (how one item installs)                                                                                      |

| **setting**              | what station sets up on a machine, or checks in it: dotfiles, logins, OS settings; named by WHAT it sets (`github-login`, not `gh`); values are asked in a form on a terminal, never argv                                                                                                                                                                                                            | script, preference (below)                                                                                          |

| **Checked**              | the settings station reads from macOS without applying them; a good one is **As expected**                                                                                                                                                                                                                                                                                                           | audit                                                                                                               |
| **Off here**             | your choice not to manage a setting on one machine                                                                                                                                                                                                                                                                                                                                                   | skipped, disabled                                                                                                   |
| **preferences**          | station's own choices, `~/.config/station/preferences.json`: this machine's name, the Macs, `vm_user`, the share list, the git identity, the ports policy                                                                                                                                                                                                                                            | settings (the section's word now)                                                                                   |

| **layer**                | where a value of a Machinefile or an item was read: `overlay`, `user`, `shared`, `built-in`, or `this machine`; a same-name file of a stronger layer replaces a weaker one whole                                                                                                                                                                                                                     | level (a Disk row's), tier (a proof's)                                                                              |
| **source**               | a set of item files and Machinefiles station reads: the owner's `~/.config/station`, one shared git repository pinned at a commit, the built-in ones                                                                                                                                                                                                                                                 | repository (any git repository), origin                                                                             |

| **share list**           | the names of the secrets that may be shared with a VM: `session:*` and the one name `operator:claude:oauth-token`; `share_list` in JSON                                                                                                                                                                                                                                                              | allowlist (generic)                                                                                                 |
| **engine**               | station's ONE background process per Mac, `station engine run` under the launchd agent `com.jterrazz.station.engine`: runs the Mac's VMs, holds the reserved ports, shares them; every surface is its client over `~/.local/state/station/engine.sock`                                                                                                                                               | supervisor, agent (taken: launchd's job and the AI agents), background process                                      |
| **hypervisor**           | the program that runs a Mac's VMs (`tart` today)                                                                                                                                                                                                                                                                                                                                                     | (the engine is station's own process)                                                                               |

## The words of the code

The architecture has its own words, used in Go and in the docs, never in the interface ([Architecture](architecture.md)):

| Word                | Means                                                                                                                                                                            |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **family**          | a top-level package of `src/`: a section's family, or a noun of its own (`machines`, `images`, `engine`, `setup`)                                                                |
| **model**           | a family's root package: its values and rules, no I/O                                                                                                                            |
| **contract**        | an interface in a family's `contract/`: one need of station from the world outside                                                                                               |
| **adapter**         | a contract's implementation for one technology, in `adapter/<tech>/`; `fake` is the one over the world                                                                           |
| **strategy**        | a contract with several adapters chosen per item at run time, through one registry                                                                                               |
| **call**            | a use case, `<family>.<verb>`, in a family's `calls/`; a **watch** is a read that fills progressively                                                                            |
| **Router**          | what decides on which machine and in which process a call runs                                                                                                                   |
| **Profile**         | what a machine is and can do: its kind, its system, its capabilities                                                                                                             |
| **capability**      | a fact a machine reports through the contract that owns it (a battery, a lid, a job manager, a hypervisor)                                                                       |
| **world**           | the fake world the spec build runs every fake over                                                                                                                               |
| **tailnet**         | Tailscale's private network, as the `Tailnet` contract names it; the interface says Tailscale                                                                                    |
| **story**           | one state of the menu bar's panel: an id of `apps/menubar/stories/STORIES.md`, its `<id>.story.json` and its goldens; never the catalog, which is what station puts on a machine |
| **golden**          | the PNG a story or a view is proved against, dark and light, drawn offscreen                                                                                                     |
| **Station Catalog** | the dev-only window over every story, `make catalog-open`; its export and gallery draw the same stories headless                                                                 |
| **live key**        | `<measure>:<machine>`, a moving number a page follows (`cpu:linux-1`), its value sent in each `sample`                                                                           |
| **notice**          | what the engine tells, of a closed list of kinds: the menu bar's HUD and the owner's notifications                                                                               |

## The verbs

A destroying verb has no synonym in the tree. One verb per meaning:

`install/uninstall/update` (apps), `init` (This Mac: named,
its shell wired, its files moved in), `add/forget` (other Macs: registered
and forgotten, never touched), `create/delete` (VMs: made and
DESTROYED; `delete` is the only destroying machine verb), `start/stop/restart`
(running state; never destroys), `allow/disallow` (the share list),
`share/take back` (copies of an account's secret), `build`
(images), `free/erase` (Disk: `free` empties what can be rebuilt and asks
nothing; `erase` deletes data, always named and confirmed), `share/stop-sharing`
(ports; `ports share` reserves one and prints its URL).

## Default names

A VM's default name is `<image>-<n>` (`linux-1`, `linux-2`, `macos-1`), `n` being the smallest integer from 1 that no VM record on any Mac uses and no Mac's name uses. A VM is not on Tailscale, so no node holds a VM's name.

`--name` overrides it: lowercase letters, digits and `-`, 1 to 40 characters, refused if taken. A Mac's name is the owner's, asked at `station init`; the recommendation is the plain model name: `macbook`, `mac-mini`.
