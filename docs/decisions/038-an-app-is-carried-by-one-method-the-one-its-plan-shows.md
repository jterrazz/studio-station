# ADR-038: An app is carried by one method, the one its plan shows

**Status:** Proposed
**Date:** 2026-11-11

## Context

[ADR-033](033-a-machine-is-declared-by-its-machinefile.md) gave a Machinefile's resolution the choice of each item's method (prefer, the system's priority, an entry's `manager`) and version, and [ADR-034](034-apply-carries-a-machinefile-the-ledger-bounds-removal.md) recorded each install by its method so removal is bounded. But the apps family chose on its own: `apps install` took the first method of the item's file that fit the kind of machine, apply handed it the item's name alone, and the inventory read an app by that one method. A plan could name `mise` while `brew` ran, a version asked was dropped, the plan said `script` where the ledger said `shell`, and an app another of its methods held read as not managed, so the plan would install it a second time. The design (machinefile-design, "Managers: one responsibility each", hard case 5) asks that an item present by another manager be adopted, never reinstalled, and that a switch be explicit, `apps move`.

## Decision

- **One order.** The order an item's methods are tried in lives once in the catalog (`Catalog.Ordered`): prefer's keys first, then the managers the system ranks (`priority`), then any other manager, then the rest (a script, a provider), a tie keeping the file's order. The resolution chooses by it with the Machinefile's system and `prefer`; the apps a machine carries are placed by it on each kind's system with none. The default install of an app is therefore the method its plan shows when the Machinefile asks no other.
- **Only what runs is chosen.** A method station has no installer for (`apt`, `github-release` until theirs land) is never chosen; the next one serves, as the apps already did, rather than being named in a plan that then ran another.
- **The method's word is the one station runs.** A step, the plan, `explain`, the inventory and the ledger name a method by the install it is (`MethodSpec.Method`): a `script:` that runs a line is `shell`, one that only hints is `app`. A Machinefile's `manager:` and `prefer:` still name file keys (`brew`, `mise`).
- **Apply passes its choice.** `apps.install` takes a method and a version; apply hands it its step's, the install runs by that method, and its outcome, which the ledger records, names it.
- **A version is pinnable where the install carries it.** Only mise's install carries a version to its manager today, so a version asked of an `npm`, `uv` or `bun` method (or of a `pin: version` method whose install carries none) is refused as unpinnable, naming the method that can, rather than installed unpinned. Each gains it with its installer's version argument.
- **An app is read by every method it has here.** One that another of its methods lists is held by that method: OK there, updated and removed by it, adopted by a plan whose step chose another, and named by the method that holds it. It is never installed again by the first. A manager's holds still count only each catalog app's default install as the catalog's: a key that another of an app's methods lists may be the owner's own install, so it keeps the manager, and an app station installed by that other method keeps it too, as an app that leans on it.
- **A switch is `station apps move <app> --to <manager>`.** It installs by the method asked first and uninstalls the old copy only once that install is in, so the command never goes missing; a failed install leaves the old copy as it was, a copy no method holds (on PATH by hand) is the owner's and kept, one its method cannot uninstall is kept and said. It asks no confirmation: the command names what replaces the copy, and nothing the owner had is lost without its replacement.

- **Managers are items.** The words that name a manager are the keys its catalog item installs by (`Catalog.ManagerKeys`): `apps move --to` and `apps update --manager` take them, and a manager key reaches every key its item manages, so `brew` and `cask` both update Homebrew's apps. The Go list of six managers (`catalog.Managers`) is deleted; v3.0's `apps update --method` stays hidden for one release and says its now-line.
- **A manager's own folders are its own, for what it carries.** A command found in mise's shims or installs is mise's for an app with a mise method on this machine, read by its listing, never a copy present another way: a shim or a project's runtime with no global one leaves the app absent, so the global copy a Machinefile asks for is installed. Any other app found there (one the owner put there with `mise use --global`, one whose method here is no longer mise's) is present another way, adopted rather than installed again. The version is read from the binary the owner's lookup found, by its path, so it answers for that copy and never for another one a manager's PATH finds first.

## Consequences

- The invariant has an enumeration test over the fake world (`src/wire/method_test.go`): every app of the catalog, on every kind of machine, for every entry a Machinefile may write of it, installs, reads back, updates and is removed by the method its step names; adoption and move are proved on every path by an item with two methods.
- A version range in a method's selector is still judged only by the resolution; the apps place an app by kind, every version kept. Apply passes the method, so the two agree on the manager; two methods of the same manager split by version range would agree on the manager only, until apply passes the install's key too (TODO, at the first such item).
- `apps move` does not touch the ledger, which is the `machinefile` family's, and is kept so, the safe side: an app station installed for a Machinefile and moved by hand since reads held by another method, so `apply --remove` keeps it and lets its record go, as ADR-034 says of any app held another way.
- The fake installer lists what a `script` or `shell` install put, which the real adapters keep no list of, so the enumeration test is as faithful as the fakes are there (TODO, a fakes-fidelity lot).
- Plans that named `script` for a line-running install now name `shell`; a Machinefile asking an npm, uv or bun method a version is refused until that installer carries one (TODO, a small lot).
